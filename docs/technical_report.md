# 技术文档：基于 LLM+EA 的昂贵优化求解器

> 面向"少量函数评价（300 次）"的昂贵单目标优化，独立设计并实现的 LLM+EA 求解器。
> 本文档包含：研究背景与两个核心创新、算法整体架构、运行说明、核心逻辑解析、
> 以及在 BBOB 风格测试问题上的初步实验结果与分析。

---

## 第一部分：背景与研究范式（简版）

**进化算法（EA）** 通过"种群—交叉—变异—选择"迭代搜索，通用但需要大量函数评价。
**昂贵优化** 中每次评价极贵（仿真、实验、训练），评价次数被严格限制（本项目 300 次），
因此传统 EA 无法直接用，需要**代理模型（surrogate）**来减少真实评价。

近两年 **LLM 辅助 EA** 主要有四类范式：

| 范式 | LLM 的角色 | 进化对象 | 代表工作 |
|---|---|---|---|
| ① LLM 即优化器/算子 | 直接生成更优解或做交叉/变异 | 解本身 | OPRO, LMEA, EvoPrompt |
| ② LLM 做算法/启发式设计 | 生成并改进代码/策略 | 程序、启发式 | FunSearch (Nature'23), EoH (ICML'24) |
| ③ LLM 做代理模型 | 免训练地预测/比较解的好坏 | 解（LLM 近似评价） | LLM-as-Surrogate (2024) |
| ④ LLM 做配置/决策大脑 | 在线选算子、选代理、调参数 | 优化流程本身 | LLM-SAEA (2025) |

**本项目属于 ③+④ 的交叉**：用 LLM 做代理来筛选候选解（范式③），并用一个调度器在线
决定何时/如何动用 LLM（范式④）。

**当前主要挑战**：LLM 幻觉与无效输出、调用成本与延迟、可复现性差、对高维连续空间
不擅长、缺乏理论保证、以及标准测试函数的"记忆泄漏"风险。本项目在工程上针对性地
处理了前三点（严格 JSON 解析+回退、成本计量、固定随机种子+平移函数）。

### 两个核心创新

- **创新一：两阶段分层 LLM 代理（粗筛 + 精判）。** 用便宜的小模型对整池候选解粗筛，
  再用昂贵的大模型对入围者精判，只对最终少数解做真实评价。本质是**成本-精度的最优权衡**：
  小模型足以排除明显差的解，大模型只在少量候选上发力。文献中鲜有对"不同规模 LLM 分层
  代理"的系统研究。

- **创新二：预算感知调度器。** 不固定"每 N 代调一次 LLM"，而是监控**种群多样性**、
  **收敛停滞**、**剩余预算**，动态决定评价几个解、以及是否注入 LLM"跳出性"新解。
  把 LLM 调用当作**急救措施**而非常规操作。文献中鲜有系统性的"LLM 调用时机决策"研究。

## 第二部分：算法整体架构

### 2.1 数据流

```
                    ┌─────────────────────────────────────────────┐
                    │            LLMEASolver 主循环                 │
                    │                                             │
  初始设计(LHS)      │   ┌──────────┐   多样性/停滞/预算            │
  ─20个真实评价────► │   │ 调度器    │◄──────────────┐             │
                    │   │(创新二)   │               │             │
                    │   └────┬─────┘               │             │
                    │        │ 决策:n_final,jumpout │             │
                    │        ▼                     │             │
  EA算子 ──候选池(50)─►│  ┌──────────────────┐        │             │
  (DE/BLX/变异)      │  │ 两阶段漏斗(创新一) │        │             │
                    │  │ 小模型粗筛 50→10   │        │             │
   LLM.propose ─────►│  │ 大模型精判 10→3    │        │             │
   (跳出解,可选)      │  └────────┬─────────┘        │             │
                    │           │ finalists(≤3)     │             │
                    │           ▼                   │             │
                    │  ┌──────────────────┐         │             │
                    │  │ Evaluator        │─更新历史─┘             │
                    │  │ 真实评价+预算计数  │                       │
                    │  └──────────────────┘  预算用尽(300)→停止     │
                    └─────────────────────────────────────────────┘
```

### 2.2 模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 测试问题 | `src/problems.py` | Sphere/Rosenbrock/Rastrigin，带随机平移防记忆泄漏 |
| 评价器 | `src/evaluator.py` | **强制 300-FE 上限**、记录历史与收敛曲线 |
| LLM 客户端 | `src/llm_client.py` | 抽象接口 + 真实 API(`ApiLLMClient`) + 离线模拟(`MockLLMClient`)，两个 tier |
| 两阶段代理 | `src/surrogate.py` | **创新一**：粗筛→精判漏斗 |
| 调度器 | `src/scheduler.py` | **创新二**：预算感知决策 |
| EA 算子 | `src/ea.py` | LHS 初始化、DE/BLX/高斯变异、多样性保持选择 |
| 主求解器 | `src/solver.py` | 串联全部模块的主循环 |
| baseline | `src/baselines.py` | 随机搜索、标准 DE |

### 2.3 LLM 客户端的双模式设计（关键工程决策）

求解器只依赖抽象 `LLMClient`，因此可无缝切换：
- **`ApiLLMClient`**：任意 OpenAI 兼容端点（aihubmix 直接可用），`small_model`/`large_model`
  两个 tier；含严格 JSON 解析与失败回退（避免 LLM 幻觉导致崩溃）。
- **`MockLLMClient`**：离线模拟——用内部 k-NN 回归拟合上下文 (x,f(x)) 并加**tier 相关噪声**
  （小模型噪声大、大模型噪声小），从而在没有 API key 时也能端到端跑通并可复现。
  **算法逻辑在两种模式下完全一致**，本文实验用 Mock 模式产出。

## 第三部分：核心逻辑解析

### 3.1 预算控制（昂贵优化的命脉）
`Evaluator.evaluate()` 每调用一次真实函数计数一次，达到 `max_fes` 立即抛
`BudgetExceeded`。所有方法（含 baseline）都经过同一评价器，保证**完全同预算对比**。

### 3.2 创新一：两阶段漏斗（`TwoStageSurrogate.select`）
```
pool(50) --小模型打分--> 取前10(shortlist) --大模型打分--> 取前3(finalists) --真实评价
```
- 只有 finalists 花真实预算；小模型承担绝大部分打分量。
- `single_tier=True` 为消融：跳过粗筛，大模型直接给整池打分。

### 3.3 创新二：预算感知调度器（`BudgetAwareScheduler.update`）
- **多样性** = 种群平均两两距离 / 盒对角线；低于阈值 → 判定塌缩。
- **停滞** = 连续无显著改进的代数；超过耐心值 → 判定卡住。
- **预算档位**：预算充足(<40%)→评价 4 个；中(40~75%)→3 个；紧张(>75%)→2 个。
- **跳出触发**：多样性过低 **或** 停滞 → 调用 `LLM.propose()` 注入跳出解。

> 为使多样性信号有意义，种群采用**多样性保持选择**（`select_diverse`）：按适应度贪心挑选，
> 但跳过与已选点过近者，避免种群塌缩成重复点导致信号恒为 0。

### 3.4 自主实现声明
EA 主循环、种群管理、DE/BLX/变异算子、两阶段漏斗、调度器、预算控制、解析与校验
**均为本项目独立实现**（纯 numpy）。LLM 仅作为被调用的打分/生成组件。

## 第四部分：实验设置与结果

### 4.1 设置
- 问题：Sphere（凸、易）、Rosenbrock（病态山谷、中）、Rastrigin（多峰、难）；维度 **D=10**。
- 昂贵场景：**最大真实评价 300 次**；最优值均为 0。
- 每个配置 **5 个随机种子**取均值±标准差。
- LLM：离线 Mock（小模型噪声 0.35、大模型 0.10）。
- 对比方法：`random`、`de`、`llm_ea_full`（双创新）、`llm_ea_single`（创新一消融）、
  `llm_ea_no_sched`（创新二消融）。

### 4.2 最终最优值（均值 ± 标准差，越小越好，300 FEs）

| 问题 | random | de | **llm_ea_full** | llm_ea_single (无粗筛) | llm_ea_no_sched (无调度) |
|---|---|---|---|---|---|
| Sphere | 30.6 ± 2.2 | 9.37 ± 4.9 | **0.34 ± 0.16** | 0.39 ± 0.16 | 0.52 ± 0.43 |
| Rosenbrock | 20731 ± 9733 | 3423 ± 1681 | **71.5 ± 53** | 474 ± 656 | 113.6 ± 97 |
| Rastrigin | 105.4 ± 8.7 | 80.4 ± 5.0 | 34.0 ± 16.8 | **33.0 ± 8.2** | 43.6 ± 12.4 |

### 4.3 LLM 成本（每次运行平均打分次数）

| 方法 | 小模型打分 | 大模型打分 | 大模型调用 |
|---|---|---|---|
| **llm_ea_full** | ~5300 | **970** | 97 |
| llm_ea_single（无粗筛） | 0 | **5292** | 97 |

> 收敛曲线见 `results/convergence.png`（三个子图，纵轴对数）。

### 4.4 分析与结论

1. **LLM+EA 显著优于传统方法。** 完整版在三个函数上均大幅领先随机搜索和标准 DE：
   Rosenbrock 上从 DE 的 3423 降到 **71.5**（约 48×），Sphere 从 9.37 降到 **0.34**。
   说明在极少评价预算下，"每一步更聪明"的 LLM 代理筛选比"多而盲"的真实评价更划算。

2. **创新一（两阶段漏斗）验证成立——成本大幅下降、质量不降反升。** 两阶段把**昂贵的大模型
   打分从 5292 降到 970（约 5.4× 更省）**，而解质量在 Sphere/Rosenbrock 上反而更好
   （Rosenbrock 71.5 vs 474），Rastrigin 上基本持平。若按 GPT-4≈20×GPT-3.5 计价，
   总 LLM 成本约省 **4.3×**。这正是用户假设的"成本-精度最优权衡"。

3. **创新二（预算感知调度器）验证成立。** 完整版在三个函数上均优于"无调度"消融
   （Sphere 0.34 vs 0.52；Rosenbrock 71.5 vs 113.6；Rastrigin 34.0 vs 43.6）。
   动态调整评价数量 + 在停滞/塌缩时注入跳出解，带来稳定收益。

4. **诚实的局限。**
   - Rastrigin（强多峰）上完整版与单层几乎持平，说明在极难多峰问题上，两阶段的排序
     增益被问题难度淹没；此时更需要更强的探索机制。
   - 结果基于 **Mock LLM**，真实 LLM 的排序能力、幻觉率、延迟会影响结论；`--real` 通道
     已就绪，换真实 API 即可复验。
   - 300 FEs、D=10、3 个函数属于"初步验证"规模；更严谨需扩到 BBOB 全 24 函数、多维度、
     更多种子并做统计检验。
   - LLM 调用本身的货币/时间成本未计入 FE 预算——在真实部署中应纳入统一的成本模型。

### 4.5 结论
在 300 次评价的昂贵场景下，本求解器用"分层 LLM 代理 + 预算感知调度"两个简单机制，
既**显著提升了解的质量**，又**大幅降低了昂贵大模型的使用成本**，两个创新点均通过消融
实验得到验证。这为"用不同规模 LLM 做分层代理"和"LLM 调用时机决策"两个文献空白提供了
一个可运行、可复现的初步证据。
